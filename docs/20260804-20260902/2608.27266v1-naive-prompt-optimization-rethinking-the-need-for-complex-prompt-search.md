## 摘要
在不同任务上高效改进自主智能体，是加速智能体AI中递归自我改进（RSI）的核心，而提示优化作为一种有前景的方法，能够提供与微调模型权重相当的性能提升，同时降低优化和服务阶段的计算成本。然而，最近的发展越来越倾向于不必要的复杂提示优化器。我们引入了朴素提示优化（NPO），一种轻量级的单线方法，使用教师模型通过回滚反馈迭代修正提示。NPO以更少的回滚次数达到与GEPA相当或更好的性能，其优势随着教师模型能力的增强而增加，这表明更强的教师推理能力可以部分替代优化器端的搜索复杂度。在交互式游戏中，NPO总体保持与GEPA竞争性，而GRPO在一些不太适用于提示优化的任务上表现更好。我们还展示了NPO优化的提示在逐字应用于其他学生模型时，能够带来类似的性能提升，尤其是在同族模型之间。总体而言，我们的初步结果表明，简单、线性的提示优化可以与 значительно 更复杂的搜索过程相匹敌。

## Abstract
Efficiently improving autonomous agents across diverse tasks is central to accelerating recursive self-improvement (RSI) in agentic AI, with prompt optimization emerging as a promising approach capable of delivering performance gains comparable to those achieved by fine-tuning model weights, while reducing computational costs in both optimization and serving. However, recent developments increasingly favor unnecessarily complex prompt optimizers. We introduce Naive Prompt Optimization (NPO), a lightweight single-lineage method that iteratively revises prompts using a teacher model with rollout feedback. NPO achieves comparable or better performance than GEPA with fewer rollouts, and its advantage increases with stronger teacher models, suggesting that stronger teacher reasoning can partially substitute for optimizer-side search complexity. In interactive games, NPO remains broadly competitive with GEPA, while GRPO performs better on some tasks less amenable to prompt optimization. We also show that NPO-optimized prompts elicit similar performance improvements when applied verbatim to other student models, especially across models within the same family. Overall, our preliminary results show that simple, linear prompt optimization can rival substantially more sophisticated and complex search procedures.

## 2. 方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想
- **NPO（Naive Prompt Optimization，朴素提示优化）**：只维护一条提示谱系（single-lineage），不使用多候选池、显式搜索算法、Pareto 选择或 beam search。每次迭代中，由「教师模型（teacher / reviser）」根据学生模型的完整执行轨迹与奖励反馈，直接将当前提示修订为下一个版本的提示。

### 2.2 算法流程（Algorithm 1）
- **输入/设置**：初始提示 P(0)，任务数据集 D，小批量大小 N，滑动窗口大小 W，教师模型 T，总迭代轮数 Y。
- **对 i = 0 到 Y−1 循环**：
  1. 从数据集 D 中采样一个大小为 N 的小批量 \(B_i\)。
  2. 使用当前提示 \(P(i)\) 在目标学生模型上执行，获得该批次的 rollout 轨迹与奖励 \(R_i\)。
  3. 构建**滑动窗口反馈**：只取最近 W 次迭代的 prompt、rollout 和奖励作为上下文，即 \( \{R_j\}_{j=\max(0,i-W+1)}^{i} \)。
  4. 将上述内容丰富的历史反馈交给教师模型 T，T 生成下一版本提示：
     \[
     P(i+1) \leftarrow T\big(P(i),\{\text{prompts, rollouts, rewards}\}_{窗口内}\big)
     \]
- **最终输出**：提示序列 \(\{P(0),...,P(Y)\}\) 以及在验证集上表现最佳的候选提示。

### 2.3 与已有方法在关键技术上的区别
- **与 OPRO 的区别**：OPRO 只给优化器 LLM 提供「之前评估过的提示 + 标量分数」；NPO 则向教师提供完整的 rollout 轨迹以及每条轨迹对应的奖励，信息量丰富得多。
- **与 GEPA 的区别**：GEPA 维护提示候选池，通过 reflection、验证集评估和 Pareto 选择来演化多棵候选谱系；NPO 则始终只沿着一条提示路径线性前进，没有显式的候选接受/选择机制。
- **教师强弱的作用**：论文的核心观测之一是——更强的教师模型加丰富轨迹反馈，可以在相当程度上「替代」优化器端复杂的搜索设计（即搜索复杂度收益递减）。

## 3. 实验设计与 Benchmark

论文建立了一套尽量公平、低方差的对比方案，核心实验设置如下：

### 3.1 Benchmark 与数据集
- **IFBench**：在可验证的约束下评估指令遵循能力。
- **HotpotQA**：多跳问答基准。
- **TextArena（22 个交互式游戏）**：包括单人和双人游戏，用于评测策略规划与决策能力，例如：

### 3.2 对比方法
- **NPO（本文方法）**：轻量单线提示优化。
- **GEPA（Generic-Pareto）**：复杂的多候选提示演化方法。
- **GRPO（Group Relative Policy Optimization）**：基于权重的 RL 微调基线（LoRA 适配器），作为提示优化与权重微调两种不同范式的对照。

### 3.3 教师与学生模型设置
- **主要学生模型**：Qwen3-8B（优化时的目标模型）。
- **教师模型由弱到强变化**：Qwen3-8B（自修订）、DeepSeek-V4-Flash-preview-0424、GPT-5.5。
- **跨学生迁移测试**：
  - 由 Qwen3-8B 优化出的提示 → 直接应用到 Qwen3-14B、Qwen3-32B（同族）、Llama-3.1-70B-Instruct、Llama-3.3-70B-Instruct（跨族）。
  - 由 Llama-3.1-8B 优化出的提示 → 直接应用到 Llama-3.1-70B、Llama-3.3-70B（同族）、Qwen3-32B、StepFun-3.7-Flash（跨族）。

### 3.4 低方差评测设计（关键方法学贡献）
1. **共享伪随机性（shared randomness）**：同一环境中所有优化方法使用相同的随机种子序列，保证从同一初始格局出发，降低实例难度差异带来的噪声，使对比更公平。
2. **约束解码（constrained decoding）**：把模型输出强制限定为「`<think>` 推理 `</think>` [合法动作]」结构，并对合法动作集合进行 token 级前缀树约束解码；即使推理 token 预算用尽，也不会把动作缺失机械地算作失败，而是按既有策略强制选择合法动作。这样能**将「决策质量」与「格式可遵循性」分离**，避免格式错误干扰方法性能比较。

### 3.5 优化预算
- **IFBench**：NPO 约 3500 rollouts vs GEPA 约 3593。
- **HotpotQA**：NPO 约 6800 rollouts vs GEPA 约 6871。
- **TextArena（22 个游戏）**：NPO 与 GEPA 各使用 408 个完整游戏 episode（NPO 为 24 episodes × 17 轮；GEPA 为 6 个伪 reflection + 18 个伪 validation episodes/cycle）。GRPO 为每个游戏约 800–1200 训练 rollouts（后续也统一在 0–408 rollout 范围内与提示优化方法对比）。
