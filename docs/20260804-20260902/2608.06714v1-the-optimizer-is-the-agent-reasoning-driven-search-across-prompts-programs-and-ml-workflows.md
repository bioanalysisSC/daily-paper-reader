## 摘要
近期用于优化提示、程序及机器学习工作流的系统通常依赖于显式的外循环控制器，如进化搜索、多臂老虎机或文本梯度方法。我们提出了一个根本不同的问题：这种搜索策略在多大程度上可以被一个单一的工具使用智能体内化？我们提出了ReASearch，一个统一的推理驱动优化框架，其中智能体自主决定评估什么、如何诊断失败、进行哪些修改以及何时验证或重启。智能体不仅仅是作为由人工设计的启发式引导的提议生成器，而是主动分析结果、分配预算，并通过持久记忆在长时程范围内优化其策略。凭借共享的智能体循环和特定领域的工具，ReASearch用完全相同的脚手架来优化提示、程序和机器学习工作流。在14个多样的任务中，它与专门的优化系统竞争力相当且大多表现更优，相比强领域特定基线实现了2%至40%的提升，并在某些情况下发现了改进先前人类最佳已知结果的方案。关键在于，我们观察到通常由显式控制器实现的复杂搜索行为，会自然地涌现自智能体的推理过程。

## Abstract
Recent systems for optimizing prompts, programs, and ML workflows typically rely on explicit outer-loop controllers such as evolutionary search, bandits, or textual-gradient methods. We ask a fundamentally different question: how much of this search policy can be internalized by a single tool-using agent? We present ReASearch, a unified framework for reasoning-driven optimization in which the agent autonomously decides what to evaluate, how to diagnose failures, which edits to make, and when to verify or restart. Rather than serving only as a proposal generator guided by hand-designed heuristics, the agent actively analyzes outcomes, allocates budget, and refines its strategy over long horizons through persistent memory. With a shared agent loop and domain-specific tools, ReASearch instantiates the exact same scaffold to optimize prompts, programs, and ML workflows. Across 14 diverse tasks, it is competitive with and mostly better than specialized optimization systems, achieving gains of 2% to 40% over strong domain-specific baselines, and in some cases discovering solutions that improve on prior human best-known results. Crucially, we observe that complex search behaviors, which are typically implemented by explicit controllers, emerge naturally from the agent's reasoning process.

### 二、方法论：ReASearch 的核心思想与技术细节

**1. 核心思想**
将优化本身转化为一个顺序推理问题：智能体在每一轮主动决定"评估什么、如何诊断、编辑什么、何时验证/重启"，并通过持久记忆在长时程中优化自身策略。

**2. 目标形式化**

论文将优化目标形式化如下：

- 对于任务实例 x ~ D、文本制品 z ∈ Z，系统生成输出 Y ~ P(·│x,z)，获得奖励 r(x,Y)；
- 目标是找到最优制品 z*，使得期望奖励最大化。

式中 z* = argmax E_{x~D} E_{Y~P(·│x,z)} [r(x,Y)]，当目标独立于输入实例（如算法发现/几何优化）时，外层关于 x 的期望自然消去。

**3. 普通智能体架构**
- 代码智能体（code agent），配备：文件 I/O、Python/Bash 执行器、`compact()` 上下文压缩工具、持久化 `lessons.md` 记忆文件。
- 核心循环是任务无关的：所有任务特定信息仅通过两个接口注入（工具集 A_T + 任务特定系统提示），因此同一个智能体脚手架可跨三类任务复用。
- `python exec` 是核心工具——它将智能体从纯文本推理器转变为"计算理性器"，能自主编写分析脚本、计算评估统计量、识别失败模式。

**4. 三类任务的具体设计**

| 任务类别 | 工具 | 优化对象 | 关键特点 |
|---|---|---|---|
| Prompt 优化 | `get_next_minibatch`、`call_student_model_batch`、`validate_candidate` + python exec | 学生 LLM 的系统提示词 | 只给聚合验证指标（避免过拟合）；智能体自由决定批量大小、测试哪些例子、何时验证；最终提示词不取最高验证分数者，而由推理结合全史合成 |
| 程序进化 | `evaluate`、`edit_code`（子代理执行编辑）| Python 程序 | 验证子代理检查编辑有效性；分析诊断保留在主智能体内维持上下文；强调基于假设的改进（如数学抽象压缩搜索空间）|
| ML 工作流优化 | `run_experiment`、`edit_train_file`、git 命令 | 训练脚本 | 智能体可直接读代码并选择改进切入点（超参、架构、损失、优化器、正则等）；用 python exec 分析训练曲线、诊断不稳定性 |

**5. 关键机制**
- **上下文压缩与内存**：token 超阈值时自动压缩对话历史，保留状态快照 + 摘要 + lessons.md；`lessons.md` 记录"什么有效 / 什么无效 / 接下来试什么"。
- **方差鲁棒验证**：在提示词评估高方差场景下，智能体自行采用"先廉价通道验证、再昂贵正式验证"的策略。
- **无硬编码搜索策略**：整个搜索策略（分支选择、验证时机、重启决策、预算分配）全由智能体推理内生决定，是"无控制器"（controller-light）框架。

### 六、主要结论与发现

1. **ReASearch 在几乎全部任务中优于或匹敌专用优化系统**，提升幅度 2%~40%（具体如 Terminal-Bench 从 GEPA 的 42.22% 提升至 53.33%；ARC-AGI-2 测试准确率相比 AdaEvolve 提升 4 倍）。
2. **可超越或逼近人类已知最优解**：Circle Packing 中 n=32 达到 2.940（超过此前人类最佳 2.939）；Heilbronn n=11~15 达到 0.03552/0.03260/0.02700/0.02429/0.02034，与人类最佳记录一致或极接近。
3. **复杂搜索行为可以内生涌现**：包括候选双验证、基于假设的修正、复用过往失败经验、主动回滚、预算约束下的自适应探索——这一切不需要任何额外的启发式控制逻辑。
4. **同一裸脚手架（仅改变工具和提示词）即可跨三类任务通用**，天然实现"控制器内化"。
5. **组件消融显示 memory 与 python exec 均重要**：前者对长时程 prompt 优化影响更大，后者对 ARC-AGI-2 等模式识别/算法发现型任务影响更大。
6. **验证反馈粒度影响泛化**：只暴露聚合验证指标避免了过拟合，暴露逐样本轨迹反而会导致性能下降。
7. **ReASearch 不依赖特定闭源模型**：开放骨干（GLM-5、Kimi-2.5）也展示出系统性的基线提升，且效果与骨干能力成比例。
