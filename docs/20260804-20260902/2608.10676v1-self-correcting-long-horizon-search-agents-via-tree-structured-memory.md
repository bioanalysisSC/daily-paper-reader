## 摘要
基于大语言模型（LLM）的搜索智能体通过与外部环境的多步交互来回答问题。然而，将完整执行轨迹提供给LLM会导致上下文无限增长并引入噪声。现有压缩方法在减少上下文的同时牺牲了重要细节，且常常替换错误事实而不修复由其衍生的下游推理。为解决此问题，我们提出ReTree，一种用于搜索智能体的自我纠正树状存储机制。ReTree构建有界的逐步推理上下文，同时保留源链接证据。它将搜索建模为证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与先前声明矛盾时，ReTree追溯至该声明引入的节点，替换过时证据，重新生成摘要，剪除受影响分支，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并确保最终声明可追溯至检索到的段落。在四个公开问答和搜索基准上的实验表明，ReTree持续优于完整轨迹ReAct，答案准确率最高提升25.6个百分点（pp）；完整轨迹ReAct的平均最大逐步推理上下文为ReTree的$1.27$--$1.51$倍。这些结果确立了ReTree作为长程搜索中有效的自我纠正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于 LLM 的搜索智能体通过"推理—检索—再推理"的多步循环回答跨文档的复杂问题。这一过程不断将新观察、中间结论与来源元数据追加到轨迹中，使每步推理上下文随搜索深度无限增长；同时，检索本身可能引入噪声或过时/矛盾信息，一旦作为中间前提参与后续检索与推理，就会形成**错误级联**。
- **现有方法的缺陷**：轨迹压缩（如滚动摘要、报告重构）能控制上下文规模，但往往丢失每条事实与来源的绑定，以及事实在推理中的"引入位置"；简单替换错误事实并不能让依赖该旧事实的下游结论失效。换言之，**压缩与可修复性之间存在矛盾**。
- **核心问题**：一个可靠的长程搜索记忆必须同时满足三个需求：有界的逐步推理上下文、事实级溯源（claim-to-source）、与依赖一致的修订（被修订结论所依赖的下游状态须被同步失效或重算）。
- **整体含义**：作者主张搜索智能体的工作记忆不应只是一段更短的转录文本，而应是一种**可编辑的结构化状态表示**，具备带来源证据的修订能力；该思想源自 AI 领域的 truth-maintenance（真值维护）传统。

## 2. 方法论：ReTree

### 核心思想
- 将搜索过程维护为**证据树（evidence tree）**：树中每个节点是从父节点活跃证据推导出的一个搜索状态；节点内保存该步局部引入的原子证据（与来源相绑定）；边表示"子状态由父状态的证据推导而来"。
- 策略（policy）每步**只看**当前节点的摘要 + 按相关性筛选出的 top-k 证据（k=5），从而获得**有界上下文**；完整证据路径保留在外部树结构中，避免把无关历史堆进 LLM 上下文。

### 节点结构
每个节点定义：

\[
n = (s_n, E_n, H_n, p_n)
\]

- \(s_n\)：不超过 140 词的紧凑任务状态摘要（含待填空槽、已解中间槽、未解槽、候选）；
- \(E_n\)：该节点本地引入的原子证据；
- \(H_n\)：修订历史；
- \(p_n\)：父节点指针。

沿根到该节点的路径上全部证据构成该点的累计证据 \(A(n)\)。

### 逐步推理上下文构造

\[
C_k(M_t, q) = s_{n_t} \| \mathrm{TopK}_k(A(n_t), q \| s_{n_t})
\]

- 即：摘要 + top-5 按词法相关性筛选的证据；
- 由于摘要和单条证据均有界，逐步推理上下文为 O(1)，不随轨迹长度增长。

### 冲突检测与修订（核心创新）
- 新证据先经"冲突提议"：仅在同一实体、同一属性、同一 scope 与时间下给出的**不相容取值**才提议回溯；不同维度/不同实体语义/竞争但兼容的候选则直接扩树。
- 再经"历史感知确认"：综合分支摘要、目标证据的变更历史防止值反复摇摆。
- 一旦确认冲突，定位到引入被反驳事实的节点 \(\iota(j)\)，执行：
  1. 替换该节点的证据文本与来源 URL；
  2. 追加修订记录到 \(H_\iota\)；
  3. **仅依据修正后的累计证据重新生成该节点摘要**；
  4. **剪除该节点全部后代**（硬剪枝）；
  5. 令当前节点 \(n_t = \iota(j)\)，从修正点恢复搜索，让后续检索**重新构建**被剪掉的依赖链。
- 该操作实例化 truth maintenance 系统的"依赖导向反演"原则：改变前提必须使依赖结论失效。

### 证据溯源与最终答案
- 证据对象有稳定标识符；最终答案的每条声明映射到证据标识符，再经映射解析到当前证据文本和 URL，最终绑定到原始检索段落。评价时用 NLI 判定原段落是否蕴含声明，确保溯源可达。

### 算法主循环（文字版）
策略输入当前摘要与 top-k 证据 → 输出检索查询或停答；若停答且当前证据支撑问题则终止；否则检索（每次最多 5 个段落并抽取至多 6 条与问题相关的原子事实）→ 与当前路径的 top-k 相关证据做冲突检测 → 确认回溯则执行"定位/替换/重生成/剪枝/恢复"，否则将新事实作为子节点扩树。

## 3. 实验设计与基准

- **数据集**：四个公开问答/搜索基准，共 2,149 题：
  - Bamboogle（125 题，全量）
  - 2WikiMultiHopQA（600 题固定子集）
  - HotpotQA（600 题固定子集）
  - FRAMES（824 题，全量，另取其中固定 600 题做归因诊断）
- **指标**：
  - 答案质量：GPT-5 判定准确率（judge accuracy）+ 归一化精确匹配（EM）；
  - 溯源：引用精确率/召回率/F1 与无引用率（基于 NLI 的段落蕴含）；仅在该 600 题 FRAMES 子集上做诊断（因需逐声明抽取与段落级蕴含判定）；
  - 上下文与算力：每问最大逐步策略上下文（字符）、总模型调用次数与 token 用量。
- **对比方法**：
  - **Full-Trajectory ReAct**：标准 ReAct，保留完整观察轨迹（不压缩）；
  - **FlatUpdate**：与 ReTree 共享摘要、top-5 证据预算与冲突检测器，但证据存于**扁平列表**，冲突时原位替换事实而**不**定位引入节点、不重建摘要、不剪除下游（对照 Mem0 式记录记忆）；
  - **ReportMemory**：每次检索折叠入单一演进报告（上限 200 词），仅保留无序 URL 集合，无事实依赖谱系（对应 ReSum/IterResearch 等综合摘要方法）。
- **检索后端与骨架**：主干为 Qwen3-8B 策略；同一 Google Search API；每问至多 8 次搜索（每次至多 5 个段落）；至少一次真实检索后才可回答。

## 6. 主要结论与发现

1. ReTree 在全部四个数据集上显著优于 Full-Trajectory ReAct：judge 准确率提升 8.3–25.6 pp（总体 2,149 题提升 13.9 pp，EM 提升 7.4 pp）。
2. ReTree 在每个数据集上都超过 FlatUpdate 2.2–4.7 pp，证明"结构化、依赖一致的修订"优于"有界上下文+原位平替"。
3. ReTree 在 Bamboogle、HotpotQA、FRAMES 上超过 ReportMemory 1.7–7.2 pp，在 2Wiki 上仅低 0.3 pp，总体高出最强聚合基线 ReportMemory 3.0 pp。
4. 上下文控制：Full-Trajectory ReAct 平均峰值逐步推理上下文为 ReTree 的 1.27–1.51 倍；随检索步增长，完整轨迹呈发散式膨胀，而有界记忆方法（ReTree/FlatUpdate/ReportMemory）稳定在窄带内。ReportMemory 的峰值上下文最小，但准确率比 ReTree 低 3.0 pp，说明"只压缩不保留结构"不够。
5. 归因：在 FRAMES 600 问诊断上 ReTree 的引用精度/召回率（44.5/41.3）高于 Full-Trajectory ReAct（37.7/27.1）和 ReportMemory（16.8/21.4）。ReportMemory 虽无引用率最低（5.9%），但其引用的段落与声明的实际支持关系弱，即"有引用而支撑不足"。
6. 真实检索中裂缝真实存在：9.6–17.5% 的 ReTree 运行触发了回溯，验证了模型所解决问题的现实显著性。

## 7. 方法亮点

- **问题建模新颖**：将搜索记忆需求形式化为"有界上下文 + 溯源 + 依赖一致修订"三个联合要求，并用集合包含式关系（式 4）清晰定义"被修订证据的所有依赖者应被失效或重生成"。
- **思想来源明确**：将 truth maintenance（Doyle 1979）的核心原则移入 LLM 搜索循环，赋予"错误级联→结构修复"以严谨的学术谱系。
- **机制设计务实**：
  - 原子证据以"整数标识 + 自含陈述 + URL"存储，URL 由段落索引绑定而非让 LLM 复述 URL，避免不可验证引用；
  - 冲突提出与确认分成两阶段，加入 scope/time 约束与历史确认降低假阳性与振荡；
  - 硬剪枝被明确论证为"安全优先"的代表性策略，并指出其对活动搜索分支是合理的取舍。
- **对比构造有说服力**：FlatUpdate 设计成机制对齐的对照组，与 ReTree 仅有"结构/定位/剪枝"这一变量差异，能干净地分离依赖导向修订的贡献。

## 8. 不足与局限

- **实验层面的局限**：
  - 仅 Qwen3-8B 一个骨干；缺少对更大或更强 LLM 的泛化证据；Full-Trajectory ReAct 可能受长上下文能力较弱的模型拖累，结论在支持超长上下文的模型（如 GPT-4 级别）上未必等幅成立；
  - 归因诊断仅限 600 问 FRAMES 子集，且未把 FlatUpdate 放入报告；报告性方法（ReportMemory）的引用质量系统性偏低可能受其自身生成格式与后验重构机制影响，非相同条件下的归因公平对比；
  - 缺少推理性消融（如不同 k、摘要长度、冲突阈值、有无确认阶段的变体）与统计显著性检验；
  - 部分正文从属关系在第 2Wiki 等数据集上差异小于 1 pp，论文没有解释该数据集为何（可能是结构较为规整、天然冲突少或链式前提对错分开）相对优势更小。
- **机制本身的固有局限**：
  - 硬剪枝把"在谱系上是后代"当作"语义上依赖"的保守代理，会过度失效仍有效的中间状态，造成冗余重检索与重生成；
  - 修复质量受冲突判定器准确率限制：假阴性保毒（错误继续传播），假阳性过度剪枝；
  - 仅约束逐步推理上下文，外部存储仍可能无界增长，线性证据选择与树遍历在长程任务中会变慢；
  - 延迟与额外模型调用（比 FlatUpdate 多 7–11% 调用）未提供端到端延迟结果，实际部署成本被部分掩盖；
  - 本质上是单会话搜索的工作记忆，无长期记忆通用能力；如需跨任务长期记忆还需配合其他系统（如 MemGPT/HippoRAG 等）。
