## 摘要
提示优化器自动搜索能提升语言模型性能的提示，但现有方法依赖预定义的优化流程：算法决定探索哪些候选以及搜索如何推进，而语言模型则生成或细化提示提案。我们引入了RLMOpt，一种提示优化器，通过递归语言模型（RLM）使搜索策略本身由语言模型驱动。该RLM智能体在基于工具的环境中运行，检查任务信息、分析失败、生成候选、分配评估预算并决定何时停止。一个确定性框架通过强制客观评分、基于帕累托的选择和回归约束来补充智能体。我们在四个基准上评估RLMOpt，涵盖结构化临床信息提取（Chia）、多跳问答（HotpotQA）、可验证指令遵循（IFBench-2025）和多轮工具调用智能体（BFCL）。在单个种子的配对比较中，RLMOpt在所有四个基准上获得最佳留出分数，并以四项任务平均值领先（0.610对比GEPA的0.589）。在多种子下重复每个基准，共产生11次匹配的基准-种子比较，其中RLMOpt在9个案例中优于GEPA。在所有11次运行中，它从未生成低于其种子表现的提示，而GEPA有两次低于其起点。它还更高效，以更少的搜索部署实现了这些结果，同时生成的提示大小为GEPA生成提示的27-79%。我们的结果进一步表明，优化收益主要取决于种子提示中可用的提升空间，而非搜索预算。因此，高效优化取决于以最少搜索可靠地达到可用的提升空间。

## Abstract
Prompt optimizers automate the search for prompts that improve language-model performance, but existing methods rely on a predefined optimization procedure: the algorithm determines which candidates to explore and how the search progresses, while the language model generates or refines prompt proposals. We introduce RLMOpt, a prompt optimizer that makes the search policy itself language-model-driven through a recursive language model (RLM). The RLM agent operates over a tool-based environment, inspecting task information, analyzing failures, generating candidates, allocating evaluation budget, and deciding when to stop. A deterministic harness complements the agent by enforcing objective scoring, Pareto-based selection, and regression constraints.   We evaluate RLMOpt across four benchmarks spanning structured clinical information extraction (Chia), multi-hop question answering (HotpotQA), verifiable instruction following (IFBench-2025), and multi-turn tool-calling agents (BFCL). In a matched comparison at a single seed, RLMOpt obtains the best held-out score on all four benchmarks and leads the four-task mean (0.610 against 0.589 for GEPA). Repeating each benchmark across seeds yields 11 matched benchmark-seed comparisons, in which RLMOpt outperforms GEPA in 9 cases. Across all 11 runs, it never produced a prompt that underperformed its seed, whereas GEPA fell below its starting point twice. It is also more efficient, achieving these results with fewer search rollouts while producing prompts that are 27-79% the size of those produced by GEPA.   Our results further show that optimization gains are determined primarily by the headroom available in the seed prompt, rather than by the search budget. Efficient optimization therefore depends on reaching the available headroom reliably and with minimal search

## 1. 论文的核心问题与整体含义

**研究动机/背景：**
- 现代 AI 系统高度依赖多阶段语言模型流水线，其性能强烈依赖于提示词（prompt）的质量。
- 然而，人工设计提示词费时费力且难以跨任务/组件迁移，因此提示词优化（prompt optimization）成为解决该问题的重要方向。
- 现有的提示优化器（如 GEPA、MIPROv2、OPRO）虽然引入了任务反馈，但**高层搜索策略（search policy）仍然是预定义的固定算法**：算法自身决定候选如何生成、评估哪些候选、如何度量进展；语言模型仅在其中扮演"候选生成器"或"精修器"的角色。

**核心问题：**
- 能否让语言模型本身来控制/自适应地决定优化流程，而不只是参与候选生成？即能否将**搜索策略本身**交给语言模型驱动，使优化器在任务间表现出自适应的行为？

**整体含义与核心主张：**
- 论文提出的核心观点是：搜索策略不应预先固定，而应由一个递归语言模型智能体（RLM agent）在工具化的环境中自主控制——包括检查任务信息、分析失败原因、生成/精修候选、分配评估预算、以及决定何时终止搜索。
- 同时，为了防止"自适应"蜕变为"验证集过拟合"或"逐字段拆东墙补西墙"，不能把决策和客观评估都交给语言模型：需要一个确定性的框架（harness）来强制客观评分、帕累托选择与防回归约束。**智能体负责探索方向，确定性框架负责客观裁决**——这是 RLMOpt 设计的核心分权思想。

## 2. 方法论：核心思想、关键技术与流程

### 2.1 核心设计思想：分离"决策"与"执行/裁决"

| 组件 | 角色 | 职责 |
|---|---|---|
| RLM Agent（gpt-5.1） | 搜索策略/控制器 | 检查任务信息、分析失败、提出候选、分配预算、决定何时停止 |
| 确定性 Harness | 客观执行器 | 执行任务 LM、计算所有分数、维护候选历史、强制帕累托选择与防回归约束 |

### 2.2 关键技术细节

**（1）Agent 的动作模式（REPL）**
- 遵循递归语言模型（RLM）框架，agent 不输出固定动作符号，而是每轮编写一段短程序（代码），在 REPL 沙盒中调用一个或多个工具并读取其输出。
- 工具接口包括四类：内省工具（查看任务/数据/指标）、失败分析工具（定位失败案例）、合成工具（调用子模型做摘要/合并）、评估与状态工具（运行候选、提交候选、查询预算等）。
- 每次 `run_candidate` 返回的是**结构化反馈记录**而非单纯分数（含逐字段得分、不匹配字段、判定理由等），便于 agent 直接精准定位问题。

**（2）确定性框架的选择与约束**
- 复合分数：\( S(p) = \sum_f w_f s_f(p) \)，其中每个输出字段有权重 \( w_f \)，要求权重和为 1。
- 帕累托选择：在多输出字段情况下，候选 p 支配 q 当且仅当所有字段 \( s_f(p) \geq s_f(q) \) 且至少一个字段严格更大；最终候选从帕累托前沿中按复合分数挑选。
- **防回归下限**（防字段倒退）：每个字段的得分不得低于当前最优的 \( b_f - 0.05 \)，即不允许为了整体上升而牺牲某一字段超过 5%。该约束在所有报告实验中都处于激活状态。
- **统计显著门槛**：候选相对运行最优的提升须超过 1.65 个标准误（单侧 95% 阈值），防止单次验证集噪声造成伪提升。

**（3）自适应终止条件**
- Agent 可按以下三个条件自行停止（提示词中写明，但非硬性）：① 所有字段平均验证分 ≥ 0.85；② 已消耗 ≥ 80% 搜索预算；③ 连续两个候选未能将复合分提升至少 0.02。
- 实际运行中，0.85 的目标几乎不可达，0.02 的阈值又小于标准误（0.03–0.05），因此预算上限是主要的有效约束。作者在 Limitation 中坦承停止策略存在校准问题。

**（4）诊断门控（Diagnose Gate）**
- 若连续评估 3 个候选分数与运行最优几乎无差异（落在噪声带内）且无诊断动作，`run_candidate` 将报错并强制要求 agent 先对其最弱字段调用 `synthesize_failures` 做子模型驱动的失败分析后才可继续。其目的是防止 agent 浪费预算在一串统计上无差异的候选上。
- 该门控有界：连续两次拒绝后自动放行一次评估，防止死锁。

**（5）多组件候选（面向工具调用智能体）**
- 把优化单元从单一字符串泛化为组件映射 \( c = \{name_k \mapsto \text{text}_k\} \)：单提示任务仅含 `system_prompt`；工具调用智能体则额外包含各工具的 `tool_description_<name>` 和可优化示例组件。
- 对工具调用智能体，评分对象从"单轮答案"扩展为**轨迹**（工具调用序列 + 最终答案 + 最终状态），支持确定性指标与可选的 LM 逐步判定。

**（6）后处理定稿阶段（Polish 阶段）**
- 在 agent 搜索结束后，harness 会额外生成至多 5 个变体（结构化重写、追加 3/8/15 个金标示例、子 LM 重写），与种子、已提交候选、agent 声称最优的候选一起进入最终帕累托前沿竞争。该阶段的评估不计入搜索预算。

## 6. 主要结论与发现

1. **主结果**：在单种子（seed 7）匹配对比中，RLMOpt 在 Chia、HotpotQA、IFBench-2025、BFCL-mt **四个基准的留出集上全部取得最优分数**（0.568 / 0.727 / 0.460 / 0.686），四项均值 0.610 高于 GEPA 的 0.589。
2. **跨种子稳健性**：在 11 次基准–种子匹配对比中，RLMOpt 胜出 9 次；且**从未低于其种子提示的表现**，而 GEPA 有两次低于种子起点。
3. **样本效率**：RLMOpt 在更少下游 rollout（固定 500 ≈ GEPA 的 60–65%）条件下达到更优结果；更小的预算（B=200 或 135）也可以回收大部分增益。
4. **提示简洁性**：RLMOpt 优化出的提示为 GEPA 优化结果的 27–79% 大小（BFCL-mt 上 5,419 字符 vs. 19,818 字符），即"更小但更强"。
5. **核心认识（headroom 假说）**：优化收益主要由种子提示相对于任务 LM "提示能力天花板"的**剩余可利用空间（headroom）**决定，而非由搜索预算决定。当提示已接近天花板时，增加预算几乎无济于事，换更强的底层模型才有效。
6. **过拟合风险**：合成诊断任务显示，在验证集较小时加大搜索预算可能降低留出集准确率（0.769 → 0.385）。

## 7. 方法或实验设计的优点

- **分权架构富有洞见**：将"自由探索"（语言模型智能体）与"客观裁决"（确定性 harness）分离——两个组件各自承担最擅长的工作，既保留了自适应的灵活性，又避免了纯语言模型驱动时难以维持一致性保证的问题。
- **结构化反馈设计**：每次评估不仅给一个分数，而是提供逐字段分解、不匹配字段和判定理由，使智能体无需额外诊断调用即可有针对性地修改——这种设计显著提高了搜索效率。
- **防回归下限 + 统计显著门槛 + 帕累托选择的三重保险**：在自适应搜索的语境下显得尤为必要和合理，能在小验证集下有效抑制过拟合和逐字段间的"跷跷板"行为。
- **诊断门控机制**：针对自适应智能体可能空耗预算于统计无差异候选的病态行为，施加了有界、可恢复的干预，不失为一个通用 RL 环境设计中值得借鉴的反空转策略。
- **评估协议公平**：同一种子、同一数据切分、统一任务 LM、逐示例匹配对比、报告配对标准误——报告方式较诚实（不掩盖差异在噪声范围内的事实）；关闭技能库以避免跨轮信息泄漏也是加分项。
- **对"何时优化无益"的分析**（天花板/无提升空间领域）本身是有价值的负结果研究，指出了领域内往往被回避的重要问题。
- **自动停止条件下的样本效率评估**：比单纯报告固定预算下的结果更贴近真实使用场景。

---

## 8. 不足与局限

### 8.1 方法层面

- **停止策略校准不佳**：论文自述三个停止条件中的两个（0.85 目标、0.02 阈值）与实际基准不匹配，导致预算封顶成为唯一有效约束。停止策略导致的运行间方差（rollouts 在 21–500 之间）尚未得到解决。
- **系统性归属缺失**：RLMOpt 与基线差异被多种因素同时贡献（自适应策略、复合评分、防回归、示例组件、抛光阶段），作者未做逐组件消融来识别何者贡献最大，限制了对方法机理的深入理解。

### 8.2 实验充分性层面

- **基准覆盖面有限**：4 个基准均为英文 API 模型（gpt-4.1 / gpt-4o-mini），未扩展到开源模型、小模型或中文等非英语场景。
- **边际效应量级偏小**：多数差异（+0.006 到 +0.033）与其标准误（0.014–0.051）相当，只有 BFCL-mt 和 HotpotQA 的差异超过 1 标准误；"RLMOpt 整体更优"的结论更多依赖跨基准/种子的一致性，而非单项巨大优势。
- **种子数量有限**：3+2 个种子，还无法构成高置信度的概率性结论（例如 "RLMOpt 总是能守住种子" 这一主张在 Chia seed 13 和 HotpotQA seed 13 上实际输给了 GEPA）。
- **BFCL 对比中的不对称**：RLMOpt 优化了 GEPA wrapper 未暴露的 demonstrations 组件，作者亦承认该基准上的差距应归于完整系统（而非纯自适应策略）。

### 8.3 过拟合与天花板风险

- **合成诊断显示验证集小则过拟合风险放大**（预算增加反而降低测试准确率）；混合函数调用任务也观察到"验证集提升但留出集下降"（Δ≈−0.03）的负面结果。
- 所有主基准都特意选择了存在提升空间的种子——该方法在接近天花板的任务上不会带来额外增益（作者将其定位为负控制实验，而非主结果）。

### 8.4 工程与算力黑盒层面

- 实验严重依赖商用 API（gpt-5.1 作为优化器 LM、gpt-4.1/gpt-4o-mini 作为任务 LM），成本被转嫁给 API 供应商，无法在本地完全复现。
- 未披露"优化器 LM 推理带来的全部 token 开销"（仅在表 5 单独报告了 token，但未与具体美元成本挂钩的完整清单）。

## 总结性评价

RLMOpt 代表了提示优化领域一个值得关注的方向转变——从"改进预定义优化器内部的候选生成机制"转向"让语言模型本身作为搜索策略的控制器"。其核心贡献并非追求某一数据集上的大幅提升，而是展示了一种**可靠、高效且不损害种子表现**的自适应优化框架。分权设计（agent 搜索 + 确定性 harness 约束）是一大亮点；停止策略未校准、消融不足、基准覆盖面较窄是其主要短板。该工作对领域的一个重要提醒是：**知道何时不该优化（不能优化）也是有效优化的一部分**——这个洞见值得后续工作在更广的模型/任务谱系上进一步验证。
