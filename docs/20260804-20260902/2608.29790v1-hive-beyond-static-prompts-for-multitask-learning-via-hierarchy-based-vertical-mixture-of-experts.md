## 摘要
随着大型语言模型（LLM）规模的持续扩大，参数高效微调（PEFT）已成为全参数适配的实用替代方案。提示调整是有效的，但现有方法要么采用扁平提示结构，要么采用具有固定提示组合的层级结构，限制了自适应提示特化。为解决这一局限，我们提出了HiVe，一种提示调整框架，它能在多个层级建模提示，并实现依赖输入的特化。HiVe通过在训练期间利用任务间关系构建提示层级，并在推理时采用垂直专家混合（V-MoE）机制，将提示组合到每个输入所需特化级别。实验表明，HiVe在多样化任务中始终优于强提示调整基线。

## Abstract
As large language models (LLMs) continue to scale, parameter-efficient fine-tuning (PEFT) has become a practical alternative to full-parameter adaptation. Prompt tuning is effective, but existing approaches either use flat prompt structures or hierarchical structures with fixed prompt composition, limiting adaptive prompt specialization. To address this limitation, we propose HiVe, a prompt tuning framework that models prompts at multiple levels and enables input-dependent specialization. HiVe constructs a prompt hierarchy by leveraging inter-task relationships during training, and employs a vertical mixture-of-experts (V-MoE) mechanism at inference time to compose prompts up to the level of specialization required for each input. Experiments show that HiVe consistently outperforms strong prompt tuning baselines across diverse tasks.

# HiVe：基于层级垂直专家混合的自适应提示特化

## 1. 核心问题与研究动机

随着大语言模型规模不断增长，全参数微调的成本日益高昂，参数高效微调（PEFT）成为主流方案；其中提示调整仅学习少量软提示参数，同时保持骨干模型冻结。然而，现有提示调整方法存在两个核心局限：

- **扁平提示结构**：早期方法使用单一共享提示，无法覆盖多任务、多领域下的数据分布多样性。
- **固定层级组合**：虽然有些方法引入层次化或多级提示，但通常使用固定的任务相关路径或固定提示组合，不能根据输入内容自适应地选择“专业化程度”。

由此引出的核心问题是：**如何让每个输入在不依赖任务 ID 的情况下，动态选择所需的提示规格化级别？** 不同输入可能需要不同程度的共享知识和任务专有知识：有的只靠通用基础提示即可回答，有的需要中等粒度的“分组”信息，有的则必须使用任务级甚至更细粒度的专有提示。现有方法把所有提示当作同一抽象层面的并行专家来处理，难以同时捕捉一般共享知识与任务特有信息。

## 2. 方法论：HiVe 框架

HiVe 的目标是让提示层级本身成为可路由的空间，从而实现**输入依赖的自适应专业化**。核心思想是构建「基础提示 → 分组提示 → 任务提示」三层提示层级，并使用“垂直专家混合”机制，根据输入查询特征决定下钻到层级中的哪一深度。

### 2.1 整体架构

- **提示层级（Base–Group–Task）**：\(P_B\)、\(P_G\)、\(P_T\) 分别对应基础、分组和任务提示，均位于低秩空间 \(R^r\)，并使用投影矩阵 \(W\) 映射到模型嵌入空间。
- **两阶段训练**：
  - **阶段一**：学习基础提示与任务提示，并使用基于稳定性的任务聚类，形成临时两层结构；
  - **阶段二**：引入分组提示完成三层结构，同时训练路由键，使每个输入能被导向合适的提示层级。
- **推理阶段**：无任务 ID，只需用输入查询与各路由键计算相似度，选择得分最高的键决定最终提示组合。

### 2.2 残差式提示分解

为防止共享信息全部堆积在任务提示中，HiVe 在训练前对提示做两次“减法式”分解：

- **基础–任务分解**：将任务提示的全局均值视为共享部分 \(P_{sh}\)，把它从各任务提示中扣除并转移给基础提示：
  \[
  P_T^{(\tau)} \leftarrow P_T^{(\tau)} - P_{sh}, \quad P_B \leftarrow P_B + P_{sh}
  \]
- **分组–任务分解**：任务分组确定后，将同一组内任务提示的均值视为组共享表示，将其从任务提示中扣除并赋给对应分组提示：
  \[
  P_T^{(\tau)} \leftarrow P_T^{(\tau)} - P_{sh}^{(c(\tau))}, \quad P_G^{(g)} \leftarrow P_{sh}^{(g)}
  \]

这一做法使各层级分别承担通用/组级/任务级信息，降低了层级内外的冗余与干扰。

### 2.3 基于稳定性的层级构建

- 阶段一中，任务提示 \(P_T\) 随训练逐步编码任务特征。
- 每隔 \(N\) 步，计算任务提示平均向量的余弦不相似矩阵，并用层次凝聚聚类（HAC）生成分组。
- 为了避开“分得过早则不准确、分得过晚则训练不足”的矛盾，引入**稳定性准则**：每次聚类结果 \(c_s\) 与此前 \(K\) 次结果计算 ARI，若平滑后的 MeanARI 超过阈值 \(\eta\) 且连续 \(R\) 次触发，才最终固定分组并进入阶段二。

### 2.4 垂直专家混合（V-MoE）

V-MoE 采用**基于键的路由机制**，而非普通 softmax 路由：

- 任务键 \(k_T^{(\tau)}\) 可学习；基础键和组键通过取质心得到：
  \[
  k_B = \frac{1}{n}\sum_\tau k_T^{(\tau)},\quad k_G^{(g)} = \frac{1}{|T_g|}\sum_{\tau \in T_g}k_T^{(\tau)}
  \]
- 查询 \(q = xW^\top\) 与不同层级键计算余弦相似度。
- 训练损失为“两级交叉熵”（任务级和组级预测），提示构造仍使用真实层级完整路径，避免路由错误干扰提示学习。
- 推理时 \(k^* = \arg\max_k \cos(q,k)\)；若选中基础键则只使用 \(P_B\)；选中组键则用 \(P_B+P_G\)；选中任务键则用完整路径 \(P_B+P_G+P_T\)。

## 5. 主要结论

1. **域内性能**：HiVe 在 MRQA 上平均 F1 为 75.4，摘要 ROUGE-L 为 26.1，均超过全量微调，并显著优于所有提示类基线；例如 MRQA 上比 SMoP 高 2.1 点、比 PT-MoE 高 2.6 点。
2. **域外泛化**：MRQA 上 HiVe 平均 F1 为 62.8，比 SMoP/PT-MoE 提高 1.4/2.2 点；摘要上为 16.8，比两者提高 0.7/1.3 点。
3. **消融验证**：残差分解、三级层级、V-MoE 动态路由三部分均有效；静态策略都有明显性能损失，说明“不同输入需要不同专业化深度”。
4. **分组分析**：任务间语义相似的能形成稳定组（如问答中的 TriviaQA+SearchQA、摘要中的 Giga+XS）；ARI 指标随训练上升并稳定。
5. **路由分析**：不同任务对层级选择有不同偏好，固定层级必然次优。
6. **扩展验证**：即使换成 Llama-3.1-8B，HiVe 仍以更少参数获得更高平均分；推理开销与普通提示调整可比。

## 6. 方法亮点与优点

- **解释性较强**：基础/分组/任务三层提示有明确语义分工，可通过分解和聚类可视化理解任务关系。
- **残差分解的设计** 巧妙避免了层级间信息耦合，提升了后续聚类与路由的效果。
- **稳定性驱动的层级构建**：用 ARI 滑动窗口等准则防止过早分组，兼顾了“学到足够任务特征”和“保留充足训练时间”的矛盾。
- **键的质心推导** 比独立学习上层键更稳定，可减少对单任务表示偏差；两级交叉熵同时监督任务级和组级路由，层次信息得到更充分利用。
- **参数极简**：约 87K 可训练参数（约 0.007% 模型参数）即可达到或超过全量微调效果，且输入侧无额外可学习参数，没有改变模型结构，兼容各类 Transformer。

## 7. 不足与局限性

### 局限性（作者自述与分析）

- **分层敏感与稳定性依赖**：任务分组依赖于随机种子、提示长度、低秩维度及各分组超参数；某些配置可能过旱结束分组，导致分组结构与下游性能不稳定。
- **OOD 范围有限**：验证的是“同任务、换输入分布”的分布漂移，尚未覆盖“任务类型完全变化”或更大幅度的分布迁移。
- **硬路由能力有界**：即便自适应选择级别，也无法挖掘超出已学会层级结构之外的新模式，深度级跨任务泛化仍受限。

## 8. 总结

HiVe 提出了一种较有启发性的多任务提示调整思路：把提示做成按层级组织的“垂直专家”，并通过基于键的路由让每个输入决定“往提示层级走多远”。实验显示出其在问答与摘要两大类任务上的全面优势，尤其在域外泛化上优于扁平 MoE 方法和固定层级方法。作者也坦诚指出了任务分组稳定性、跨任务泛化范围等局限。未来更值得探讨的路径包括软路由、top-k 垂直路由，以及让层级结构根据更新到达的任务动态扩展，从而把自适应特化从“层内选择”推广到“结构本身动态变化”。
