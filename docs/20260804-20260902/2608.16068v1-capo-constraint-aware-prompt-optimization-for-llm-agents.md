## 摘要
大型语言模型（LLM）正越来越多地被部署为智能体，这些智能体依赖系统提示来使用工具并完成任务。此类部署提出了独特的运行要求，包括适当地使用工具、简洁的提示和解决方案路径，以及遵守安全和格式策略。然而，对于许多从业者而言，收集领域特定的监督数据来对模型进行后训练以满足这些要求是不可行的。我们提出了CAPO（约束感知提示优化），一种原始-对偶方法，它结合了基于池的重写与自适应约束加权，以在明确的运行约束下优化系统提示。在智能体基准测试中，CAPO在提升任务性能的同时，更可靠地达到经验可行的操作点。CAPO还能泛化到智能体场景之外，在具有输出格式以及安全/隐私约束的助手式评估中取得了强劲的结果。我们进一步提出了DCAPO（动态训练的CAPO），它在冻结任务智能体的同时，使用基于池的GRPO训练一个基于反馈和对偶条件的重写器。在不同规模的任务智能体上，DCAPO在每个评估领域都产生了可行的提示，并匹配或提高了评估基线所达到的任务准确率。一个替代分析描述了有限池和离散重写误差如何进入不精确的原始-对偶过程。

## Abstract
Large language models (LLMs) are increasingly deployed as agents that rely on system prompts to use tools and complete tasks. Such deployments impose distinct operational requirements, including appropriate tool use, concise prompts and solution paths, and compliance with safety and formatting policies. For many practitioners, however, assembling domain-specific supervised data to post-train models to meet these requirements is infeasible. We introduce CAPO (Constraint-Aware Prompt Optimization), a primal-dual method that combines pool-based rewrites with adaptive constraint weighting to optimize system prompts under explicit operational constraints. Across agentic benchmarks, CAPO more reliably reaches empirically feasible operating points while improving task performance. CAPO also generalizes beyond agentic settings, achieving strong results on assistant-style evaluations with output-format and safety/privacy constraints. We further introduce DCAPO (Dynamically Trained CAPO), which trains a feedback- and dual-conditioned rewriter with pool-based GRPO while keeping the task agent frozen. Across task agents of different sizes, DCAPO produces a feasible prompt in every evaluated domain and matches or improves the task accuracy achieved by the evaluated baselines. A surrogate analysis characterizes how finite-pool and discrete-rewrite errors enter the inexact primal-dual procedure.

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 CAPO（约束感知提示优化）

- **核心思想**：采用**原始-对偶（primal-dual）优化**框架，将系统提示作为原始变量，将约束违反程度通过拉格朗日乘子（对偶变量）引入优化目标，从而在优化任务性能的同时控制约束满足情况。
- **关键技术组件**：
  1. **基于池的重写（pool-based rewrites）**：维护候选提示池，每次迭代通过 LLM 重写器从池中生成新的候选提示，并在池中择优；
  2. **自适应约束加权（adaptive constraint weighting）**：对偶变量根据迭代中的约束违反情况进行动态调整，对难以满足的约束赋予更高权重；
  3. **可行性导向**：优化过程不仅追求任务性能最大化，更强调经验可行性——即到达满足全部约束的可操作（feasible）区域。

- **算法流程概要**（文字描述）：
  1. 初始化提示池，包含一个或多个种子提示；
  2. 对每个候选提示在评估集上运行任务智能体，获得任务性能指标与各项约束违反指标（如工具使用错误率、格式错误率、安全违规率等）；
  3. 计算经验约束违反程度，并据此更新各约束对应的对偶权重（拉格朗日乘子）；
  4. 利用重写器对池中的提示进行改写，生成新一代候选提示并加入候选池；
  5. 依据“任务性能 − ∑对偶权重 × 约束违反”的增广目标在池中筛选提示；
  6. 重复步骤 2–5，直至达到经验可行操作点或预算耗尽，最终输出满足约束且性能良好的提示。
- **对偶条件的直觉**：如果一个约束长期被违反，其对偶权重上升，提示选择时会更强烈地惩罚该约束的违反，从而引导重写器优先修复该约束。

#### 2.2 DCAPO（动态训练 CAPO）

- **扩展动机**：CAPO 需要多次查询重写器与评估智能体，成本较高，且重写器是固定的。DCAPO 旨在让重写器自身变得更强，以减少推理时开销并提升约束满足能力。
- **核心设计**：
  - **保持任务智能体冻结**：不对底层任务模型做任何参数更新，确保部署可行性；
  - **训练重写器**：使用**基于池的 GRPO（Group Relative Policy Optimization）**来训练一个**以反馈和对偶条件为输入**的重写器；
  - **条件和反馈输入**：重写器在生成新的提示时接收历史反馈（如哪些约束被违反、任务性能如何）与当前对偶权重信息作为条件，从而能更有针对性地改进提示。
- **训练流程概要**：
  1. 冻结任务智能体，初始化可训练重写器与候选提示池；
  2. 用当前重写器对池中提示进行批量改写，得到一组候选提示；
  3. 在评估集上运行冻结的任务智能体，获取每组候选的任务精度与约束违反向量；
  4. 用 GRPO 计算组间相对优势，结合对偶权重构造奖励信号，更新重写器参数；
  5. 更新对偶权重并同步反馈到重写器的条件输入中；
  6. 反复迭代，直到重写器能够稳定产出可行且高性能的提示。

#### 2.3 理论分析（Surrogate Analysis）

- 论文以**替代分析（surrogate analysis）**刻画有限池与离散重写带来的误差如何影响原始-对偶过程的收敛行为，即：
  - 候选池有限 ⇒ 对真实最优值的逼近存在离散化误差；
  - 重写是离散的符号操作 ⇒ 梯度信息不连续 ⇒ 对偶更新存在偏差；
  - 理论结果给出了这些误差如何传播到近端原始-对偶不动点/收敛区间上，为方法的实用性提供了理论支撑。

4. **不依赖任务特定监督数据**：整个方法仅利用运行约束定义与通用评估信号，无需收集领域监督数据进行后训练即可生成高质量提示；
5. **理论刻画**：给出了有限池 + 离散重写导致的误差如何进入不精确原始-对偶过程的解释，为此类方法的适用边界提供了依据。

---

### 7. 优点（亮点）

- **问题切入精准且实用**：聚焦于真实部署中最常见的困境——无监督数据但需满足系统级约束——而非假设可以随意微调模型，选题实用性强。
- **原始-对偶引入提示优化**：将约束优化理论引入离散符号提示搜索过程，形成了较新颖的方法论框架；自适应对偶权重能使优化过程动态聚焦在最难满足的约束上，具备透明性与可解释性。
- **池式重写与重写器动态训练的流程设计完整**：CAPO 的“评估 → 对偶更新 → 池内重写 → 筛选”闭环和 DCAPO 的“基于反馈+对偶条件重写器 + 池式 GRPO”形成递进关系，结构清晰，工程可落地性强。
- **冻结任务模型，保持部署友好**：DCAPO 只更新提示重写器，不改变部署中的任务智能体，在防止过拟合风险和降低部署复杂度上具有显著优势。
- **广泛验证场景**：从 agentic 到助手式再到不同模型规模，验证了方法的普适性；
- **提供理论支撑**：虽然理论仅是替代形式，但在该研究方向中仍属可贵，能解释有限池误差的影响机制；
- **有丰富的后续研究价值**：为未来结合约束满足的自动提示优化和 LLM 智能体自我改进提供新方向。

---

### 8. 不足与局限

- **算力信息缺失**：文中或元数据未报告训练/推理算力开销、GPU 型号与时间成本，导致读者难以评估方法在资源受限场景下的实际可行性。
- **对评估集的需求仍然存在**：虽然不需要领域监督数据来训练任务模型，但约束优化过程仍需要对任务智能体进行多轮 rollout 评估，在评估成本昂贵或无法获得可靠验证集时可能受限。
- **提示工程依然依赖基础模型能力**：CAPO/DCAPO 的效果高度依赖 LLM 重写器的改写能力；如果底层重写模型的能力不足以表达修复方案，则约束优化可能陷入局部停滞。
- **约束定义的先验性**：方法要求以可计算的形式预先定义约束及违反指标，而现实中某些约束（如安全性、隐私性）难以自动量化，存在度量偏差风险。
- **理论分析仅提供替代性收敛刻画**：作者本人在描述上也谨慎地将其定位为 surrogate analysis，对真实离散搜索过程的收敛保证仍有限。
- **基线对比的完整性需要凭原文进一步确认**：元数据仅显示与“评估基线”对比，没有列举所有对比算法的完整明细；只有阅读完整论文才能判断是否有遗漏重要近邻方法或显著性检验缺失。
- **对多任务提示/混合约束场景的普适性**：目前评估主要为单任务/单助手提示的优化，若提示需要同时服务多种任务且约束相互冲突，方法的对偶更新和重写聚焦策略是否仍然稳定需要进一步探索。
